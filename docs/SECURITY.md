# Security — implemented versus planned

## Local source/domain boundary — 2026-10-18

Owner operations require the loopback owner cookie and origin/host/CSRF checks; bearer credentials cannot use owner routes. Named agents have explicit capabilities/scopes/project grants and expiry/revocation. Private processing grants bind one immutable source version and do not enable general retrieval. Task renewal rotates the lease; submission rechecks current credentials, grants, coverage and exact evidence. Owner review stays separate from agent confidence/provenance.

Originals and revisions retain exact hashes. Managed history is committed transactionally; direct tampering fails closed and preserves changed bytes. Large-catalog caches invalidate on observed edits and periodically verify their complete projection. Credentials, delivered records and evidence are freshly checked; derived indexes confer no permission. Trace records and receipts retain IDs/revisions/budgets/timing/query digests, not returned source text. Retrieved prose remains untrusted reference material.

URL capture bounds public HTTPS, pins validated numeric addresses and revalidates redirects. HTML uses a bounded worker. PDF text extraction uses bounded local child processing without rendering/actions/OCR/external resources; this is not an OS sandbox. Workflow/conversation imports are inert and explicit. Backups contain private originals; restore disables old credentials/grants. No public listener, cloud knowledge write, automatic AI agent or startup task is installed.

Foundation: loopback-only runtime, exact Host/Origin checks, cross-site denial, request IDs, no-store, redacted configuration/error responses, body limits and safe static paths. S07/S08 protect organization routes; remaining knowledge routes are unavailable. MCP config rejects remote/API URL credential injection. Database tests accept only exact loopback atlas_test:55432 and local target ID; test secrets are generated into ignored .local configuration. N02 now provides a separately checked live setup runner; disposable tests never fall back to cloud.

Configuration presence never grants vault access. Test-only signed identity adapters exist outside the production entrypoint and are rejected by createApp in production mode. No runtime environment flag can install one in the real server. No production auth bypass, provider API or raw source capture exists. No real secrets are committed.

S06 now implements local SQL RLS and non-owner authorization with narrow SECURITY DEFINER metadata helpers, fixed empty search_path and revoked PUBLIC execution. Private ACL tables remain inaccessible. Explicit workspace predicates prevent colliding UUIDs from crossing owners. Current evidence intersection hides restricted derivatives/edges; task purposes expose assigned chunks, never complete source-version bodies. Workers prove a current fenced lease and cannot approve memories. See AUTHORIZATION.md for the exact boundary and limits. S07 still adds bound-owner/domain HTTP authorization. S09–S23 add actual ingestion, disclosure/grant services, review and MCP; SQL tests do not certify those future services or production.

N01 now implements real managed Auth/JWT verification for connection diagnostics, not vault ownership. Restricted runtime atlas_api has no elevated membership, superuser or BYPASSRLS. Admin URLs pulled by CLI are never used for API queries. TLS uses verify-full. setup receipt table has forced RLS matching transaction-local verified issuer/subject; missing/wrong identity reads no rows. No stored tokens/passwords/emails in that table. Valid unrelated users cannot read another identity's receipt and cannot access knowledge. Owner binding remains required.

S05 (local only) installs all 39 domain tables with RLS enabled and no application CRUD grants. No S05 SECURITY DEFINER helper or permission bypass exists. Composite workspace FKs, kind/partition checks, immutable history and exact span/hash constraints are verified, but do not substitute for S06 audience/agent/worker policy tests. Setup workspace/seeding services are not exposed through HTTP and require a caller-managed setup transaction plus later explicit owner binding.

Auth SDK browser adapter responses are runtime validated; its incompatible published declaration graph is contained at an explicit JS adapter with a narrow checked TS consumer. No skipLibCheck/strict weakening. CSP allows only self plus the exact configured Auth origin for connections. Tokens stay in managed SDK/session memory and request headers, never URLs/logs/localStorage added by ATLAS. Sign-out cannot retroactively invalidate an already-issued JWT; server enforces expiry. Live test recording is disabled; test credentials and env files are gitignored. Existing managed email delivery was inspected as disabled, so no signup/sign-in email was sent.

S07 resolves a verified issuer/subject only when both exactly match the configured installation owner. The narrow private resolver returns user/workspace IDs for an enabled owner membership; every content query then uses withPrincipal and RLS. Binding is setup-only, serialized by an advisory lock, idempotent for the same enabled owner, refuses another existing owner and never enrolls a first visitor. The local CLI validates target and genuine branch JWT, redacts failures and cannot target Neon. Actual owner binding is deferred.

S08 organization mutations lock the workspace, check expected revisions, reject unknown actor/identity fields and require scoped idempotency keys. Collection merging preserves canonical item IDs and manual locks/origins/exclusions; contradictory manual decisions reject and roll back. No collection mutation modifies access grants. On logout/identity change the UI cancels and clears queries; failed authorization refresh hides retained data. Controlled browser tests use a dedicated local-only test entrypoint, synthetic signed JWTs and intercepted managed Auth responses. No real login/signup/email operation was performed this milestone.


## N02 live backend boundary

The exact authorized ATLAS production schema and private bucket are deployed. Admin/direct migrations require checked project/branch/host/login and a complete matching child-rehearsal receipt; runtime API/worker logins have no owner membership or BYPASSRLS. The actual S3 anonymous request returned403. Credentials remain server-only and the verifier can delete only its own newly generated object after a run-marker check. No bucket-wide deletion or public source route exists.

The prepared owner:bind:neon command separately verifies a genuine branch JWT and explicit owner identity, binds under setup-only privileges, and saves only issuer/subject metadata. It has not selected an actual owner; test identities are never promoted. Source capture/reconciliation and personal C1 acceptance remain pending. See NEON_DOMAIN_SETUP_REPORT.md.


## N03 — trusted connection-receipt owner selection

An administrator-only setup mode can bind an explicitly selected email from a fresh server-written atlas_setup.auth_checks receipt joined to the managed Auth profile. It accepts exactly one match, exact configured issuer/subject-profile linkage and a receipt no older than10 minutes with no future timestamp. Synthetic example.invalid accounts are refused. The receipt is written only after the existing genuine JWT verifier accepts the connection-check request; email alone is not identity proof. The selected personal account followed the owner's instructed login/check/Done sequence. No public enrollment route, token extraction, password request or auth bypass was added. Runtime requests still require valid JWTs and current owner membership.
